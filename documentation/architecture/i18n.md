# Interface language

Sefer's own words (menus, buttons, messages) are **Paraglide messages**: one typed function per
message, `m.some_id({ … })`. Scripture text is never touched by any of this; a project's language
and direction are the project's.

- `src/app/messages/{locale}.json`: the catalogs, ICU MessageFormat (`{count, plural, …}`,
  `{kind, select, …}`). `en.json` is the source; a message missing from another locale compiles
  to the English, so a half-translated language never shows an id.
- `project.inlang/settings.json`: the locales and the ICU plugin (`@inlang/plugin-icu1`, loaded
  from `node_modules`, so a build never fetches from a CDN).
- `src/app/paraglide/`: generated, self-ignored. `pnpm i18n` compiles it; `pnpm typecheck` and
  `pnpm install` (`prepare`) run that first, and the Vite plugin keeps it current under `pnpm dev`.
- `src/app/locale.ts`: the interface language as one Solid signal, `uiLocale()`.

## Writing copy

New copy is a message. Add it to `en.json` with an id in snake_case, screen first
(`reference_search_placeholder`), search the catalog for an existing message before adding one,
and call `m.<id>()` where it renders. `tsc` rejects a misspelt id, a missing argument and a wrong
parameter name (parameter VALUES are typed `unknown`). Never compute a message at module load:
the language can change while the app runs, so a table of copy holds functions or ids, not
strings.

The old `t("…")` (`src/app/i18n.ts`) is English-only. It goes away screen by screen, as
screens are touched; there is no gate on it (Will, 2026-10-22).

## Choosing the language

The setting is `ui.locale` (Settings → App appearance → Language): a locale tag, or "" for
Automatic, the best match of the browser's languages (full tag, then language: `es-MX` → `es`),
else English. `applyLocale` sets the signal and `<html lang dir>`.

A change does NOT reload the page (Will, 2026-10-22: "don't want to lose undo history cause
someone decided to change a lang or accidentally did"). Paraglide's `getLocale` reads
`uiLocale()`, and `LocaleScope` in `src/routes/__root.tsx` keys the screens on it, so a change
remounts every screen while the open project, its books and their undo history (in
`ProjectProvider` and the services, above the scope) stay as they are.

Every `Intl` formatter and `toLocale…` call in the app takes `uiLocale()`. Not: text Sefer writes
for other people (a suggestion's title), and `localeCompare("en")` where an order must be stable.

## Direction

`<html dir>` follows the interface language (`getTextDirection`). Layout uses logical properties
(`ms-`, `pe-`, `start`, `end`), so it mirrors; the editor's text direction is the project's, set
on the editor surface, independent of the interface.

## Bundles

Paraglide never lazy-loads a locale (https://paraglidejs.com/blog/dont-lazy-load): each message's
module carries every locale, and a bundle keeps only the messages it uses. At today's size that
is an estimated 15–20 KB gzipped per locale; measure again at about ten locales. Per-locale
static builds are deliberately not used: they need one build and one route per language.

## Tours

A tour's `audience` is `field` (part of the product; its words become messages) or `internal`
(a note to the PO and designer about a design and its trade-offs, English, design builds only,
outside the catalog). No field tutorial has shipped yet, so every tutorial today is internal;
the verse-number workflow is field.
