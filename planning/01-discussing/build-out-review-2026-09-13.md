## What is genuinely good

The one-write-path invariant holds end to end: keyboard, `apply`, windows, satellites, fixes, replace, revert, recovery and multi-book all converge on `fromView → accept` / `book.apply`; publication is synchronous over a snapshot of the subscriber set; `fromCanonical` + `filter: false` make the window round trip non-recursive; the plain Book's revision is continued by the editor-backed one so stamps survive the seat swap. The UTF-16 contract is stated once at the wall (`parse(…, utf16: true)`, `find::wire`), checked at runtime (`buildStructure` throws on a UTF-8 dish; `fromSnapshot` drops a UTF-8 publication whole), and both hosts' `CorpusEngine.find` share one decoder. `finding.ts` really is the one place two dialects become one shape, with a semantic id. `Fixes.preview` checks three different things for three different mistakes and says why. `corpus.rs` is a textbook owner thread. `services.ts` is one readable page of wiring with a sentence per Layer, and the host-guarded dynamic import verifiably keeps `@tauri-apps/*` out of the Web bundle. Comments overwhelmingly explain *why*; there is no `any`, almost no `as`, and every stub that cannot do its job throws or returns a typed `Unsupported` rather than an empty list. `pnpm boundaries` still proves core imports nothing host-shaped.

## Correctness risks

**Save / external changes.** `save` (saveCoordinator.ts:278) checks `conflicts`, which is populated only by `externalChanges(source)` (l.438) — a Stream no shell code runs; `resolve` has no caller either. The vision's save protocol step 3 ("validate external-change expectations against the relevant disk identity") is not implemented; the seams' `Conflict(onDisk differs from baseline)` was meant as a save-time check. Fix: before `writeFileAtomic`, stat/hash the file and compare to `baseline` (hash when both sides have one, else canonical text); fail `Conflict` on mismatch. Wire `externalChanges` into `ProjectContext.openProject` under the project's scope so watch-capable hosts also get the early warning.

**Recovery.** `restore` (recovery.ts:404) applies `entry.changes` in before-text coordinates to whatever text `resolveBook` returns, with no check that `entries[0].before` describes it (not even length). `pending` compares `last.after.revision` to a baseline that after a restart is `None` (baselines live in `saveCoordinator.ts:213`, in memory) or `adopt`'s `r0`, so every on-disk journal is offered. The only thing keeping the on-disk journal equal to "unsaved edits" is `compact` succeeding after every save; save.md documents that a failed compact is "noted, never fatal", which is exactly the case that double-applies on restore. `Recovery.journal(book, receipt, changes, projectId?)` dies on misuse and has no caller. Ruling 1 of the build-out notes (journal vs the vision's §13.2 snapshot) should be decided in favour of the snapshot: a snapshot with the engine hash of its baseline is trivially safe to adjudicate (§13.5) and needs none of the replay machinery. If the journal stays: refuse `restore` unless `entries[0].before.length === book.source().stamp.length` and store the baseline's engine hash in the header.

**Shell subscriptions.** ProjectContext.tsx:294-298 — `recovery.attach` is inside `focus` with no guard, `autosave` is guarded by `armed` (a `Set<BookId>`); both finalizers are registered in `runtime.scope` and run only at `dispose()`. `closeProject` closes the Project but Save, Recovery and ProjectAnalysis keep their `book.changes` subscriptions on the dead Books, and `SaveCoordinator.seen` keeps them reachable. Opening a second project with a book of the same id skips autosave for the new Book (armed by id). `ProjectAnalysis.attach` (projectAnalysis.ts:376) re-attaching clears `entries` but the previous attach's `unsubscribes` map and `project.changed` listener are only released by its own finalizer — also app-scoped. Fix: give each open project a child `Scope` (`Scope.make` → `Scope.close` in `closeProject`), run `openProject`, `attach`, `autosave`, `recovery.attach` in it, and key `armed` by Book identity or drop it in favour of the scope.

**Search freshness.** search.ts:415-421: the stamp attached to a projected hit is `book.source().stamp` at query time; the corpus text is `entry.stamp` from ProjectAnalysis's last pass (projectAnalysis.ts:284). Between a keystroke and the ~150 ms pass a hit is both stale and "fresh". Fix: `findProjected` takes a `stampFor(bookId)` that ProjectAnalysis answers from `entry.stamp`, or the wire carries each book's checksum and `projectedHit` compares it to `stampOf(analysis)`. Also `limit` is corpus-wide and then filtered by `options.books` (l.387-414), so a filtered search can return fewer than `limit` while more exist.

**MultiBook undo via `history.undo()`.** multibook.ts:135-138: for an editor-backed book the undo takes back the *last* history event. `pendingUndo` guarantees the revision has not moved, and `apply` isolates `project.*` origins, so it is correct today — but a later non-doc history event (a selection-only isolate) would break it silently. Worth a test (below), not a change.

**`applyAll` comment lies.** book.ts:133-137 and source.md claim overlapping ranges "are refused as out of range once an earlier splice has moved them". Sorting back-to-front means the earlier range is *not* moved by a later splice; `[0,5)` + `[3,8)` both apply and produce garbage. Either detect overlap (one pass over the sorted list) and refuse, or drop the claim.

**Editor-backed Book after `close()`.** editor/book.ts:309-315 clears `receivers` but not the port's `listeners`; `apply`/`bindView` still work after close, so a released seat can keep publishing to Save. `Project.release` (project.ts:281) rebuilds the plain Book but the old seated object stays live in `SaveCoordinator.seen`, `armed`, and the shell's `services.seated` map (services.ts:427 — never pruned). Fix: `makeListeners().clear()`, and `apply` after `closed` returns a `Refusal`.

**Origin vocabulary.** editor/book.ts:198-215 publishes `"history"` for a headless undo but CodeMirror's `"undo"`/`"redo"` when a view is bound. Same act, two receipts. `Origin` is `… | (string & {})` (book.ts:48-58), which erases the union — nothing can switch on it exhaustively.

**Effect error channels.** `src/platform/tauri/updater.ts:148-166` and `hostInfo.ts:76-79` use `Effect.promise` + `orElseSucceed`; a rejection is a defect, so going offline kills the About panel's fiber and a locale-less OS fails boot despite the comment saying it must not. `installAndRelaunch` returns `void` when nothing is installable although the port says it does not return on success. `src/platform/tauri/remote.ts:70-78` maps `NotARepository → Unavailable` (means "no transport in this build") and `Io → Rejected` (the one reason the port says is not worth retrying). `web/git.ts:95-99` reports a path missing from a commit as `Conflict`.

**Settings writes race.** settings.ts:160-180 — two concurrent `set`s each snapshot `stored`, save the whole file, then write `stored`; the second file write drops the first key. Serialize with a `Semaphore` (Save already has the shape) or queue.

**Solid.** `ProjectContext` and `FindingsFilters` fork fibers via `runtime.runFork` and interrupt them in `onCleanup` — correct. Seven oxlint `solid(reactivity)` warnings remain in `CloudPanel.tsx` (122,162,178,186), `ProjectContext.tsx:457` and two JSX-import warnings; Will's gate is meant to be clean. `runCommand` (commands.ts:148) does `void outcome` on a Promise-returning command — rejections are unhandled. `git.commit` hard-codes the author `{ name: "Sefer", email: "sefer@localhost" }` (commands.ts:441) into every commit; that is provenance in the user's history and belongs in Settings.

**Rust.** `corpus.rs:86-106`: a panic in `job(&mut sous)` (any engine panic, including inside rayon) unwinds the owner thread and every later command answers "the corpus thread is not answering" for the process lifetime with no respawn. `git_commit` with empty receipts and no HEAD creates an empty root commit (`git.rs:296-344`) where the Web layer refuses — same port, two behaviours. `credentials.rs` and the pull/push findings are in the top 10.

## Coherence with the design

- **"Effect at the edges, sync in the middle" held.** The keystroke path allocates no fiber; Streams appear only in Project.externalChanges, Settings.changes, Remote.progress, ProjectAnalysis.watch. Good.
- **Host names stay inside `src/platform`** and `services.ts`; `detectHost()` is the only sniff; `src/app`/`src/routes` import only the `../editor` barrel. Good.
- **Deviations that are drift, not rulings:** the debounce "extracted to `schedule/debounce.ts`, three callers" (build-out note 15) — `projectAnalysis.ts:221-241,450-469` still carries its own copy. `filter.ts` was added to core while `findings.ts:6-10` in the same folder still says a filter model "belongs to the shell". `usfmLinter` defaults to `hiddenByPaint` where the spike defaulted to nothing hidden — editor.md says the spike is the specification and does not list this as a change. `sinkTracer` renames rule events to `phase:name`, so any spike-shaped sink consumer no longer matches.
- **Seams the shell does not reach.** MultiBook, Diff (`compare`/`revert`/`revertAll`), Library, ProjectAdmin, `Recovery.pending/restore`, `Search.replaceInBook/planReplace`, `cloneRepository`, `gitContract` (registered in no tier), `Gitea.forkRepo/listOwnedRepos`, `HeadlessDialogsLive`, `MemorySettingsLive`, `severityOf`, `formatBook` have no caller outside their own file. That is fine for module-first work, but the build-out notes' "what exists now" table reads as if these are reachable. Say which are wired.
- **Speculative code** (against "no speculative features"): `src/app/workflows/{drafting,stet}.ts` are stubs that `Effect.die`, with typed forms nobody fills in; `recipes/attrs.ts`'s `alignedWordTooltip` throws a `TODO(seam)` from a function nothing installs. - **Glossary.** Code says `Baseline`, `Receipt`, `Refusal`, `Hit`, `Finding` consistently with the seams. `ExternalChange` exists twice with the same fields (project.ts:70, saveCoordinator.ts:90). `Seated` adds optional `attached?`/`close?` to the port — optional-property soup where the doc says a seat *must* answer both.
- **Recovery vs vision §13.2** is the one design-level conflict that needs Will's ruling (see Correctness).

## DRY / duplication

- **Freshness, four ways:** `findings/finding.ts:305` (revision), `search/search.ts:437` (revision), `diff/diff.ts:198` (revision + length + bookId), `fixes/fixes.ts:161` (revision), `multibook.ts:116` (revision). The seams say these are "the same check with different names"; make it one `isFresh(stamp, book)` in `source/` or `book/`.

- **`readJson` / `parseJson` / `lastSegment` / `isUsfm`** are defined identically in `resources/import.ts:68-70,134-143` and `resources/library.ts:163-186`; `isRecord` in `recovery.ts:158` and `settings.ts:95`; `describeError`/`messageOf` in `web/git.ts:33`, `web/remote.ts:100`, `tauri/fileSystem.ts:70`, `tauri/updater.ts:55`, `core/galley/corpus.ts:121`.

- **Hand-rolled JSON guards** in `recovery.ts:158-184` next to a codebase that decodes everything else through Effect Schema (settings, library, gitea, resources). Use a `Schema.Struct` for the journal.
- **Hand-rolled base64** in `gitea.ts:253-269` because "core has neither `btoa` nor `Buffer`" — `btoa` is not in the forbidden-globals list and exists in Node ≥ 16 and every browser; the file already uses `TextEncoder`.

## Extensibility / lego-ness

Core is not pre-baked to one of anything: Project holds many Books, Library binds many resources per open-named role, ProjectAnalysis/Save/Recovery attach per book, the corpus takes many references, `mountSatellite` mounts over any Book. The ports are narrow (Git 7 methods as user jobs, Remote 6, Credentials 3, Dialogs 3) and the Web/Tauri Layer sets are symmetric (same 8 services swapped in `domainLayer`). Two exceptions: (1) `Library.add` (library.ts:348-354) drops the `subject` that `describe` computed, so the "resources carry their subject" commit (`d83081f`) is half-landed; (2) the shell is singular by design (one `Project`, one `focused` book) and `services.seated` is a grow-only map. `Settings` cannot enumerate keys (ruling 7) — reasonable. `HostInfo.capabilities()` is declared and never read; nothing branches on `fsWatch`/`secureStore`, so the Web host's inability to watch is discovered by a `Stream.catchCause` instead of asked up front.

## Rust

Covered in Correctness (pull/push/commit/panic) and top 10 (#6, #7). Also: `capabilities/default.json` grants `opener:allow-open-path` and `fs:allow-lstat` with no consumer; `updater`/`process`/`window-state` are not `platforms`-restricted while the plugins are `cfg`-gated; `Cargo.toml` path dependency means a fresh clone cannot `cargo check`, and `pnpm check` never runs Rust so a broken `corpus.rs` reaches `main` unnoticed. ## Tests that would earn their place first

1. **Save refuses when disk moved** (`saveCoordinator`, memory FS): adopt, write different bytes to the path outside Save, `save` → `Conflict`, file untouched. Fails today: no save-time check.
2. **Recovery restore refuses a journal that does not describe the text**: journal `before.length ≠ book.length` → `RecoveryError`, book unchanged. Fails today: no check.
3. **Recovery after save+compact offers nothing; after save with failed compact offers nothing twice**: exercises the double-apply path. Fails today.
4. **Focusing a book twice journals each edit once** (ProjectContext or a Node reproduction over `Recovery.attach`): two attaches, one apply, one entry. Fails today.
5. **`dirty()` costs no engine call**: count `analyze` invocations across 100 `dirty` reads. Fails today.
6. **`findProjected` refuses a hit when the corpus is behind the Book**: register A, edit to B, find, `resolveHit` → `null`. Fails today.
7. **Publication parity**: same `Change[]` via `book.apply` (headless) and `view.dispatch` (bound) → identical receipts, one revision bump, one `changes(fn)` call each. Fails if a second write path or double publish appears.
8. **Refusal names the first door**: keystroke inside hidden markup → `Refusal.rule === "refuseKeystrokesInsideHiddenMarkup"`, doc unchanged.
9. **Window round trip keeps its caret and applies once**; refused edit leaves both texts unchanged.
10. **Tracer at level `off` allocates nothing**: ring length unchanged after a typed character. Fails today.
11. **MultiBook `undoPending` on a bound editor book restores exactly the operation** after an intervening selection-only transaction. Guards the `history.undo()` assumption.
12. **`applyAll` refuses overlapping changes** (or the doc stops claiming it does).
13. **`git_pull` refuses to clobber a dirty work tree** (Rust, two temp repos) → `Conflict`, local bytes untouched. Fails today.
14. **`git_push` reports a `pre-receive` rejection as `Rejected`**, not `Ok`. Fails today.
15. **`gitContract` registered against `WebGitLive` (browser) and `TauriGitLive` (desktop)**; `fileSystemContract` against `TauriFileSystemLive`. desktop.md asserts the latter passes; nothing proves it.
