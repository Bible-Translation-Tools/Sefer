## Rulings the owner should make

1. **Recovery: journal or snapshot?** The seams (§4.2) specify an append-only change journal replayed through `apply`; the vision (§13.2) commits to a per-book snapshot of canonical text with a checksum envelope and explicitly not a transaction log. The journal was built. It re-judges old edits under today's rules but has no snapshot fallback.
2. **Save writes canonical LF always** (open question 2 of the heart doc). The disk newline style is not remembered. If it should be, it belongs beside `encode` in the coordinator, not in `Source`.
3. **`Refusal.rule` from the editor is best-effort** — admission `changeFilter`s do not note a verdict, so a keystroke refused inside hidden markup reports `editor.phases`. Adding a note in those two rules fixes it.
4. **Sous severities are Sefer's policy** (the engine ships none): Hygiene → error, Presence → warning, the rest → info. Onion `hint` → info; `form`/null dropped at the adapter.
5. **One scheduling fiber in ProjectAnalysis, not one per book**, because `publish()` is whole-corpus. 150 ms idle, 1 s deadline.
6. **`SaveCoordinator.dirty` treats "no baseline" as dirty**, so a freshly opened book reads unsaved until touched. The shell papers over it (`unsaved(book)`); the real fix is a Save-side `adopt(book)` seeding the baseline from the bytes just read.
7. **Settings cannot enumerate registered keys**, so the settings screen renders the shell's own descriptor list rather than "every registered schema" (seams §5.2).
8. **Updater keypair.** `tauri.conf.json` carries `REPLACE_WITH_MINISIGN_PUBLIC_KEY`; the v1 key belongs to the v1 channel. Run `pnpm tauri signer generate`, put the public key in the config and the private key in the release secrets. Until then "Check for updates" errors.
9. **Updater worker.** The release workflow uploads updater artifacts to the GitHub release; the manifest worker (`workers/zephyr-updater` in v1) needs a Sefer instance and `VITE_SEFER_UPDATER_HOST` pointing at it.
10. **WACS repo topics.** v1 set a `consolidated` topic after `createRepo`; Sefer's `Gitea.createRepo` does not. If WACS write-eligibility still depends on it, add it.
11. **Desktop remote progress is a final tally**, not a live stream (git2 callbacks inside one blocking command). Live progress needs Rust-side Tauri events.
12. **Two-bound debounce is duplicated** (`src/core/save/debounce.ts` and inline in `projectAnalysis.ts`). Extract to a neutral core utility.

## Deviations from the seams doc, deliberate

- `replace(hit, insert, funnel)` and `revert(hunk, funnel)` take a `Book` — the Book is the funnel. `replaceAll` does not exist; the corpus shape is `MultiBook.runAcrossBooks` with `Search.planReplace` (vision §12.2 forbids a global Replace All).
- `census`/`analyze` on ProjectAnalysis are synchronous reads over held products; `attach(project)` does the work off the keystroke path. `navigate(finding)` became the pure `navigateTarget`.
- `Galley.attrs`/`spelling`, `formatBook`, `attrs`/`attrResolve` in the editor: the pinned handle exports none of these (see `usfm_onion_2/galley/src/wasm.md`); they are loud `TODO(seam)` stubs. Engine fix edits (`DiagnosticView.fix()`) DO work, so fix previews are real.
- `Galley.version()` reports two wire formats (onion, sous), not one.
- `Dialogs.pickFolder` on the Web returns a handle name, not a path; a handle→path registry belongs to the project/library slice.
- `Project.externalChanges()` is `{ bookId; path; kind }`; the on-disk comparison against a baseline is Save's.
- `99-BAD.usfm` decodes (valid bytes, malformed USFM) and opens as book `BAD`; `project.failed` is for byte-level refusals.
- The Git port's reads carry `GitError`; `gitContract` takes an optional FileSystem layer factory and is registered in no tier yet.
- `Project.instantiate` returns the `Book` port; the shell reads the `EditorBook` back through `services.seated(id)` rather than asserting on the port. Each book gets its own `galley.memoize()`.
- Vite `resolve.dedupe` for `@codemirror/state`/`view`: `@codemirror/lint` otherwise resolves its own state copy and the linter's facets are rejected at mount.
- `@codemirror/state` moved from the exact `6.5.2` pin to `^6.7.0`: view and commands require it, and the pin produced two copies of the state types.

## Verified live

The shell agent drove the dev build with Playwright: open the fixture project → five-book census → open PSA in a mounted `EditorView` → a keystroke moves r0→r1 and flips the dirty marker → Save writes the file and clears it → mode toggle → `Mod-K` palette → Findings lists 76 real findings → Find "Blessed" returns two hits and "Show" mounts a result card → Settings renders → History reports `NotARepository` honestly. `pnpm test:browser` passes (21). After the dedupe fix landed the lint gutter was re-enabled and checked live: PSA mounts with three lint markers in the gutter and no console errors.

## Not verified

Anything else that needs a real `EditorView` (bindView/fromView round trips, render window, atomic ranges, bidi isolates, satellites) — the spike's browser suite covered these and nothing here runs them yet. `Recovery.restore` was not exercised. Desktop: `cargo check` passes and the dev window opened with the Tauri branch taken, but no desktop file, git or keychain operation was exercised end to end; `TauriFileSystemLive` has not been run against the contract suite. Remote: nothing was exercised against a real Gitea; the Cloud panel's "not configured" branch is the one a dev build takes.
