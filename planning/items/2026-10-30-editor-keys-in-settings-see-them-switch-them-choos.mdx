## Today

Every key the editor binds is one table, `KEY_BUNDLES` in
`packages/editor/src/core/keymaps.ts`: bundles by mode, precedence, and the
preference that turns a bundle off. Settings shows one of them, the
**Verse shortcuts** switch (`editor.verseShortcuts`, `src/app/settings.ts`).
Nothing lists the keys, nothing rebinds them, and typed markers (`\q2 `) have
no switch at all.

The keys that accept an input rule are written into the rules:

- a typed verse number is accepted by **Space** (`typedVerseNumbers`,
  `core/inputRules/verseNumbers.ts`, an input handler on `" "`);
- a typed marker by **Space or Enter** (`core/inputRules/typedMarker.ts`);
- Backspace just after a verse number takes it back to a word.

<Followup id="stale-copy">
  The Verse shortcuts description in `src/app/settings.ts` still says "when it is the next verse the
  chapter is missing". Since PR 11, a number within the reference's verse count counts too, and pasted
  text and Backspace follow the same switch. The copy is now wrong, not just unpolished.
</Followup>

## The shape this could take

1. **See them.** A read-only "Keyboard" section in Settings drawn from
   `KEY_BUNDLES`: each bundle's summary, its keys, the modes it acts in.
   The table already carries everything but key labels.
2. **Switch them.** A preference per bundle that has a reason to be off:
   typed markers, poetry levels.
3. **Choose the accept key.** A preference for the key that accepts an input
   rule (Space, Tab), read by the rules instead of the literal `" "`.
