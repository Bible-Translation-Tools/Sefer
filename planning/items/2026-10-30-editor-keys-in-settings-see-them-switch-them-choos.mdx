## Built (2026-10-30, on design/editor-rules)

`packages/editor/src/core/keymaps.ts` now reads as VS Code's keymap: every
binding is `{ key, command }`, a command is the editor's action by id
(`edit.enter`, `verseNumber.accept`, `typedMarker.accept`, `poetry.indent`),
and each bundle owns its commands. The accept keys are bindings like any other:
**Space** for a typed verse number, **Space or Enter** for a typed marker.

A host lays its own bindings over the defaults through `userKeybindings`
(`mountBookEditor`'s `keybindings` option): `{ key, command }` adds,
`{ key, command: "-id" }` takes a default away, as keybindings.json does. A
binding keeps the precedence and preference of the bundle owning its command.
No host passes any yet, so the defaults are all there is.

A key bound to a printable character (Space) also runs when the character
arrives as input with no keydown (Android's soft keyboards).

## What is left: Settings

1. **See them.** A read-only "Keyboard" section in Settings drawn from
   `KEY_BUNDLES`: each bundle's summary, its commands and their keys, the
   modes it acts in.
2. **Change them.** A setting holding the person's bindings (keybindings.json's
   shape), handed to the mount as `keybindings`; a change reconfigures the
   facet live, as preferences do.
3. **Switch bundles off.** A preference per bundle that has a reason to be
   off: typed markers, poetry levels.
