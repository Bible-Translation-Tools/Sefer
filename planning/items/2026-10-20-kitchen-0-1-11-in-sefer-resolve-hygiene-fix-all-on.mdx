## 1. One resolver: `galley.resolve`

`galley.resolve(id, address, { utf16: true })` answers an address in one held text as found
(with the span, and whether it is coarser than asked), missing, or ambiguous. Its 31 cases came
from `locate.ts`, so the rules are ours, now pinned in the engine.

Sefer resolves an address in three hand-rolled ways today:

<Files id="resolvers">
```
~ packages/text/src/location/locate.ts -- resolve(toc, address), 418 lines; keep types + tocUnits/addressAt, drop resolve and its helpers
~ packages/editor/src/bookEditor.ts -- revealAddress calls resolve; placeOf is a second resolver (chapter label + verse num, by hand)
~ packages/editor/src/recipes/align.ts -- three resolve calls
~ src/app/shell/reader.ts -- arriveAt: resolve, then showChapter + aim
~ src/core/excerpts/excerpts.ts -- two resolve calls

~ src/app/workflows/stet.ts
~ src/core/galley/ -- the wrapper does not expose resolve yet; add it beside analyzeText/analyzeBook
```
</Files>

The calls hand over a `TocView`; `galley.resolve` takes the held text's id. So every caller needs
the id of the text it means, which the editor and analysis already hold. A caller that has only a
TOC (excerpts over a unit list?) is the one to check first.

## 2. Reopening a project forgets the chapter

Reopen lands on the remembered book but chapter 1 (John 3 → John 1). The same happens on the code
before the readability pass.

The place is remembered as `workspace.lastLocation` (`src/app/settings.ts`): book, chapter
ordinal, and a `place` of chapter label, verse number, offset, source hash, length.
`BookEditor` hands `place` to `editor.resume` (`packages/editor/src/bookEditor.ts`, `placeOf`):
the caret and scroll move, but nothing tells the reader which chapter to show. `arriveAt`
(`src/app/shell/reader.ts`) does both, `showChapter` then `aim`, for a link.

**Change:** remember an `Address` (book, chapter, verse) plus the offset/hash for the
unmoved-text fast path, and reopen through `arriveAt`: one arrival for a link, a reveal and a
reopen, resolved by `galley.resolve`. `placeOf` goes.

## 3. Findings ignores `?code=` on a direct load

`/project/<slug>/findings?code=sous.convention.Casing` shows every finding when loaded directly;
following an in-app link works. `FindingsPanel` seeds the code filter in an effect
(`src/app/ui/panels/FindingsPanel.tsx`, `search().code` → `filters.update({ codes: [code] })`);
on a direct load the saved filter arrives after it through `settings.changes`
(`src/app/ui/panels/findingsFilter.ts`) and the merge loses the code. Not yet confirmed which write wins.

**Change:** start the filter from the search: `createFindingsFilter(services, { codes })`, so the
code is in the first value and nothing races. Keep the effect for in-app changes of `?code=`.

## 5. Hygiene "fix all"

`snapshot.hygieneGroups({ scope: "book" | "project" })` groups hygiene rows; a group's `.fix()`
returns the certain deletions (fa_opv: 235,434 ZWNJs with no letter). Today each finding is fixed
one at a time.

This is Replace-all-shaped, and the ruling there was: no bulk rewrite by default, Advanced may.
Proposed: on a hygiene group's header in Findings, "Fix all N in this book", behind Advanced,
applied as one edit per book (one Undo), never saved until Record a version, as every edit.
