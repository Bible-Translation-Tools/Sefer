## Decline, the background

The built behaviour is in [sync](../../documentation/architecture/sync.md) and
[git](../../documentation/architecture/git.md), "Suggested changes". A plain Decline only closes the
pull request, so its versions ride along in the person's next offer. Will rejected recording a
decline as a "keep ours" commit (2026-10-07): it would reset the author's own copy.

The author's half is done (2026-10-13): a refused send leads to Review against the copy and one
decision commit, sent as a fast-forward (sync.md, "A copy that has moved on").

For the reviewer's half, two proposals:

- **Review's decision commit taking nothing** (direction of 2026-10-13, `decline-reviewer` above).
- **Remember declines by content** (2026-10-07, not ruled):

  A declined suggestion stays on WACS, closed, and Gitea keeps `refs/pull/<n>/head`. Reviewing
  the same person's next suggestion, Sefer fetches their recent declined heads and marks a passage
  offering the same text again as "Declined on 7 October", collapsed. No commit on either side, no
  new storage, the author's copy untouched. A per-passage reason, if wanted, is a pull-request
  comment or a [git note](/items/2026-10-07-git-notes-rationale).
