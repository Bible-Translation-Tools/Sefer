Thomas (designer), 2026-10-27, on branch `design/editor-design`:

> one `tab` would indent the line creating a first level poetry. `enter` would create another level 1
> poetry...but another `tab` would indent to level 2. We wouldn't go any further than level 2 as its
> not needed for our use case. While in a poetry marker, enter would add a new line, and if empty,
> would bring up a level until you got back to a normal paragraph marker.

The guiding rule:

> The idea really is to try to copy as much of Word's behavior as its a commonly used alternative our
> users use frequently. "Do what Word does" is probably a safe smart default.

## Settled

- **Refine only.** Tab keeps its current meaning everywhere else: table cells in Refine
  (`tableCommands.ts`), the next empty verse in Form Mode (`verseLines.ts`).
- **Tab** changes the line's marker one level in: `\p` → `\q1` → `\q2`. **Shift+Tab** steps out one
  level, back down to the paragraph floor. No tab character is ever written.
- **Enter** after text in a poetry line makes another line at the same level. **Enter on an empty
  poetry line** steps out one level: empty `\q2` → `\q1`, empty `\q1` → paragraph.
- **Backspace at the start of a poetry line** (before its first word, a verse number included) steps
  out one level, as Word takes a bullet off before joining lines: `\q2` → `\q1` → `\p`, then the
  next Backspace joins the line above. Thomas, 2026-10-28: "Lets start with the Word approach".
- **A selection across lines** changes every line it touches together (Word's bullets).
- **Only `\q`/`\q1` and `\q2`.** Other poetry markers already in the file are never deleted. A `\q3`
  added in USFM unlocks a third level for that chapter only.

## Thomas's answers, 2026-10-28

> the cursor being anywhere within a 'line' should affect the whole line. `tab` should affect the entire
> line...which could be a lot of content within a verse bound. Tabbing verse 3 shouldn't affect verse 4

> enter even in the middle of a q1 should create a new q1. Tabbing that new line would create a q2.

> I would probably advocate for treating p and p1 as the same thing.

> if the user doesn't want it to be on a new line, they could backspace until its back up with the verse marker.

> Users should be able to do whatever they want in USFM mode though, but if they're using our WYSIWYG
> editor, then it should be opinionated towards our own standard.

> At any point a q3+ will unlock that for the rest of the chapter. If the user deletes the out of scope
> items, it goes away again.

> Empty chapter, the only thing to do is click in that ghost area and start typing. Tab shouldn't affect that

> I'd actually like to visually render the different markers in unique ways... our requirements state
> that the user should be able to interact with all of this without that knowledge

> I also want to at least include some verse error handling and a simple context menu too.
