`mountBookEditor({ readOnly: true })` stops typing but not the download.
Getting a Book means `seatBook`, which imports the whole editing layer up front:

- the keystroke rules (insert, delete, caret)
- the commands and undo history
- the note editor

So a viewer such as the hub's still ships code it never runs. A note left
with the work puts that at about 263 KB. Nobody in Sefer has measured it yet.

## The idea

A separate entry, for example `@sefer/editor/viewer`, with a viewer mount
built only from the reading parts:

- the view and reading layers
- the linter
- location
- diagnostics

It must never import the editing modules, so a host that imports only the
viewer ships none of them. The work is mostly splitting imports so the reading
path no longer reaches `seat.ts`, the phases or the history.

## Before building

Measure the real saving with the hub-shaped test app (installed by git, a
production Vite build), before and after the split.

<Question id="worth">Is the saving worth a second entry point and keeping the
two paths apart? Build only if the measured number matters for the hub.</Question>
