## What changes for a user

A link such as `sefer://r/<owner>/<repo>` (with or without a place after it)
opens the installed desktop app at that project, the same way
`https://<sefer>/r/<owner>/<repo>` does on the Web. If the app is already running,
the link opens in that window rather than starting a second copy.

The point is an "Open in Sefer" button on WACS:

> if wacs itself wanted an "open in sefer"

## What already exists (the stack, 95fedfd)

The share-link route does all the work: `src/routes/_app/r/$owner/$repo/$.tsx`
→ `src/app/ui/landing/OpenByLink.tsx`. Checked on the r-links preview,
2026-10-14:

- **Only `/r/<owner>/<repo>` is needed.** The place after it (`/book/JHN`), `host=`
  and `at=` are all optional.
- **No `host=`:** the link is looked for on the configured cloud.
- **No `at=`:** there is no version toast.

On the dev channel, that cloud is `content.wacsdev.org`. So
`reuben-catalog/merged-blo` (which is only on content.bibletranslationtools.org)
needs `?host=content.bibletranslationtools.org` there. Without it, the app
correctly says the project isn't there.

Desktop has neither the deep-link plugin nor the single-instance plugin
(`src-tauri/src/lib.rs:32-44`).

## How

- **Rust and config (about 15 lines).**
  - Add `tauri-plugin-deep-link`, plus `tauri-plugin-single-instance` with its
    `deep-link` feature, so a second launch hands its URL to the running window.
  - Register `plugins.deep-link.desktop.schemes: ["sefer"]` in the Tauri config.
  - Add `deep-link:default` to the capability.
- **TypeScript (about 20–30 lines, desktop platform only).**
  - Call `getCurrent()` at boot, for the link that launched the app, and
    `onOpenUrl()` after that.
  - Map `sefer://r/…` to a router navigation to `/r/…`. Anything else is
    ignored.

## Where a scheme gets registered

The OS has to know that `sefer://` means this app:

- **macOS:** the bundle's Info.plist declares the scheme, and LaunchServices
  reads it once the `.app` is on disk. A local `pnpm tauri build` works: move the
  `.app` to /Applications and open it once. It doesn't need to be signed for
  this. `pnpm dev:tauri` doesn't work, because the dev binary isn't a bundle.
- **Windows:** the scheme is a registry key (`HKCU\Software\Classes\sefer`)
  pointing at the exe, written by the NSIS/MSI installer. A dev exe has no key
  unless the app calls the plugin's `register()` at runtime.
- **Linux:** the scheme comes from a `.desktop` file with
  `MimeType=x-scheme-handler/sefer`. A .deb or .rpm install ships one. An
  AppImage doesn't, so the app writes one at runtime with `register_all()`.
