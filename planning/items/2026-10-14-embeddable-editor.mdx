> The editor should be embeddable and testable in isolation. … we're not shipping a
> component. Wrapping it in a component of any framework should be trivial.

**Done 2026-10-15** (steps 1–3, `21b8e04..214164e`), tagged `editor-v0.1.0`. Two
framework-free workspace packages:

- **`@sefer/text`**: `Source` (canonical text, `offsetMap(raw)` for CRLF and BOM), the Book
  port, addresses and localized names, the engine's analysis vocabulary.
- **`@sefer/editor`**: the editor. CodeMirror, Effect, scripture-kitchen and `@sefer/text` are
  peer dependencies, so a git install resolves and there is one copy of each.

No app code imports CodeMirror; `pnpm boundaries` holds `src/` to the front door
(`packages/editor/src/index.ts`). How a host uses it is `documentation/architecture/boundaries.md`.

A host seats a Book and mounts what it shows, holding a handle of methods and callbacks, never the
view:

```ts
mountBookEditor({ parent, book: seatBook(makeBook(path, source), { analyze }), readOnly: true })
```

Mounts: `mountBookEditor`, `mountCard` (policy, clip, marks, live diff, Escape, caret, an undo
session with `cancel`), `mountReader`, `mountStamp`, `mountDiffView`, `mountReference`, and
`createAlignedGroup` over handles.

## What was ruled

- **The engine is injected and is always onion.** The host passes `Analyze` and serves the wasm.
- **No marker policy in the package.** Callers configure markers; Sefer's `\s5` stays Sefer's.
- **No UI.** The package exposes what a host draws around it: `diagnostics()`/`onDiagnostics`,
  `where`/`onWhere`, `reveal`/`revealAddress`, and `onViewport(where, source)` (`"user"` or
  `"reveal"`). Sync between instances is the caller wiring one handle's events to another's reveal.
- **Addresses** are book/chapter/verse; every method takes an Address or offsets.
- **No public view.**
- **Policies** are typed presets merged by `resolve()`; `setPolicy` changes one live.
- **`core/fixes`, satellites, sessions and the diff painting** live in the package.
- **A view may live under a hidden parent**; `onViewport` is quiet while hidden.
- **Effect stays** for now: [remove it](/items/2026-10-15-remove-effect-from-the-editor-packages).
- **The hub installs by SHA** and must be on scripture-kitchen v0.1.10.

## Proven

A hub-shaped app installed both packages from git, used the hub's own onion host, typechecked
and built with Vite, and every viewer method answered in a browser. In Sefer: the book, Find
cards, Key terms' Cancel, Review's live pane, footnote editing and the reference pane were driven.

## What is left

tests on the package's harness, one marker config per page (`extensions-global`), USFM mode's
light theme. The hub's swap (step 5) is the hub's work: the handoff is written. A lighter
read-only entry is [an idea](/items/2026-10-15-a-read-only-viewer-entry-for-the-editor-package).
